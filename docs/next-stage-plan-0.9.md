# Scientific Figure Skill 下一阶段完整改造计划

**主题：两类任务、共享语义编排、候选选择与视觉修正闭环。拟议开发系列：0.9；实际基线：Engine0.8.0。**

## Context

用户明确两项主任务：A参考图语义复刻，B自然语言生图。两者共用当前宿主、FigurePlan、构造工具和Scene引擎。0.8已有确定性绘图和工程系统；问题集中在宿主从观察/意图到模块、对象、关系及构造选择的过程，仍缺少足够明确、可调用、可复用的Skill流程。

这次改造不推翻底座，不增加第二个Agent或模型。要将现有宿主的工作从“直接猜几何、写程序”改善为“先理解结构、比较画法、按问题取证，再构造并修正”。宿主仍作视觉和语义判断，工具提供来源明确的测量、候选、约束检查和确定性执行。

本文件是完整计划，替换上一份以单张纳米图重绘为中心的执行计划；保留已完成成果、现有能力、兼容性、交付与隐私约束。本轮仅规划，不实施下面的新能力。

## 1. 产品目标与责任

| 主任务 | 输入 | 目标与过程 |
|---|---|---|
| A 参考图语义复刻 | 用户参考图、目标尺寸及可选修改要求 | 保留主要对象、必要内部结构、关系、文字和画风；参考→证据/宿主解释→模块/对象/关系→画法选择→Scene→SVG/PNG |
| B 自然语言生图 | 用户描述、目的、受众、可选风格/版式 | 将明确意图转为图结构，合理设计布局并标出假设；描述→宿主解释→FigurePlan→画法选择→同一Scene→SVG/PNG |

多素材保存和组合是两类任务的共享能力，继续使用Bundle/Composition，不单独建立第三套绘图管线。

**职责不变：** General Agent是当前执行宿主；Skill给出专业工作方法和工具；引擎执行明确几何。没有工具能够仅因创建了对象清单就宣称自动完成语义理解。相似度/边缘/候选分数不能当作“这是细胞膜”的结论。

成功标准：图画得像样、语义结构清楚、必要内容完整、主要部件可编辑、方法与来源可解释。合法素材、Recipe、基础几何和自由程序均可使用，不以Recipe命中率、路径数或测试数衡量绘图好坏。

## 4. 共享工作流

参考图或自然语言 → 当前宿主建立意图和未知清单 → 可选局部证据与素材/Recipe检索 → 宿主填写FigurePlan的模块、对象、关系 → 比较构造候选与画法 → 宿主选参数或写程序 → 现有编译/Builder生成候选Scene → 首次工程或B/U/C → SVG/PNG → 宿主按目标尺寸检查 → 定向patch/新候选 → 工程与交付。

复杂图默认先有可检查的对象与关系草稿，之后才写大量几何。简单单对象可以保持短流程，不强制产生多份文档或遍历全部工具。宿主可随时自由coding、合法检索素材、直接Scene构造；无法匹配Recipe时明确回退，不以错误模板换取流程完成。

## 5. 语义编排：复用FigurePlan，不建立第二套Scene

### 5.1 让FigurePlan支持清晰的工作阶段

现有FigurePlan0.1已经允许`construction.kind=unresolved`，并有role、must_preserve、editable_parts、unknown、source_id等字段。优先原样使用：

1. **意图阶段**：任务类型、目的、尺寸、原始描述/参考摘要、风格与允许简化。
2. **语义草稿阶段**：宿主填模块、对象、必要部件、文字角色、关系和不确定性；尚未选画法的对象保持unresolved。
3. **构造选择阶段**：宿主选择recipe/asset/direct/program，补参数、布局和部件对应。
4. **执行与修正阶段**：既有compile/Builder生成Scene，检查计划映射和实际预览；修改走正式工程事务。

这些是流程阶段，不新增四份对象图。规划草稿是输入；接受后的Scene仍是唯一当前几何、文字、transform和样式状态。

### 5.2 最小规划上下文

增加一个可选、严格校验的`planning_context`输入：只按已有计划对象/关系ID记录原始意图、局部证据引用、构造候选、选择理由、未选原因、构造策略和宿主确认状态。与plan ID/摘要和source摘要绑定；不重复存对象树、最终path、当前坐标或样式。

自由科学关系如“靶向”“触发释放”保存在已有关系的语义说明及上下文中，不因名字自动变成几何执行器。execute/check/semantic继续明确区分；没有证据时保留uncertain。

首次编译后，将该上下文作为`generation.json`内`inputs`的惰性输入快照保存，沿用receipt、Bundle和组合来源闭包；工作目录中的上下文文件不是第二个当前工程状态。“宿主确认状态”只说明当次构造输入曾被确认，不充当当前工程审批；当前性继续由已有Scene/preview绑定判断。

`generation.inputs`不会自动收集引用文件，因此必须自包含保存实际采用的测量结果、方法参数、坐标/源摘要和选择记录等受预算限制的JSON，不只写临时路径。需要随工程保留的参考视图通过现有`reference.png`及receipt保存，并分别记录原始文件摘要与实际保存视图摘要/映射，不混淆二者。缓存与未采用候选预览不是打开/渲染工程的依赖，可留工作目录；未随工程保存的原始外部文件明确标记external_not_packaged。Bundle/组合保留结构化来源快照及已有参考文件；源目录移走后，当前工程仍可重开且规划记录可读。

不随意在严格FigurePlan0.1中塞未知字段，也不新增顶层项目extra来重复保存同一份权威数据。旧记录无该输入时保持兼容；只有实际超出现有表达能力时，才单独评估协议升版，不预先升级Scene。

### 5.3 拟增入口（当前尚未实现）

| 入口 | 作用 | 不承担的工作 |
|---|---|---|
| `plan draft REQUEST --output WORK` | 根据任务类型、源/描述、画布建立合法草稿、来源绑定和待补清单；宿主填写语义内容 | 不通过模板偷偷理解图片或给自然语言补实验步骤 |
| `plan check PLAN --context CONTEXT --phase semantic` | 检查ID/来源/引用、必要部件声明、未知项和关系模式，列出待确认/待构造项 | 不认证对象识别或科学关系正确 |
| `plan suggest OBJECT_REQUEST` | 返回实际可用Recipe/资产及direct/program路线的适配信息 | 不自动选首个候选或写Scene |
| `plan check … --phase construction` | 检查已选构造、参数、部件覆盖、资源/字体/Scene能力和可编译性 | 不把参数合法当视觉接近 |
| 现有`plan compile/review` | 按明确选择编译，核对结果映射与当前Scene | 不执行保存程序，不暗改用户编辑 |

Python侧提供对应少量函数，CLI只是文件桥。不建立新的Agent循环、表达式DSL或庞大的独立Planner框架。

### 5.4 Skill本身的专业指导必须落地

不是只新增请求Schema：在Skill中提供可按需读取的两份任务指南和一份画法选择表，指导当前宿主完成以下判断，并配小型完整示例。

- 参考任务：先判断整图的信息结构与阅读顺序；区分实体、流程、解释引线、放大/剖面、图例和装饰；列出每个对象不可省略的内部结构、前后层次、文字和颜色意义，再填写草稿。低清处标出具体未知，不凭主题常识补造。
- 自然语言任务：先抽取用户明确的对象、动作/关系、标签和风格要求；区分必需内容、设计选择与科学假设；决定信息层级和模块后再落布局。用户未要求的制备/给药等步骤不自动加入。
- 选择画法：先问“需要哪种形态、哪几个部件、是否重复、是否有孔洞/遮挡、哪种画风”，再看实际候选；不按对象名字直接套模板。复杂对象先画主结构和必要部件，看到实际预览后才细化。

宿主可用这些问题生成结构化草稿，工具辅助检查遗漏并提供候选；工具不会代替宿主作上述解释。这样补的是可复用的专业流程，而不只是更多表单。

## 6. 构造候选与Registry检索

### 6.1 可解释本地检索

增加`registry search`，复用现有固定条目和`recipes.describe`。检索输入包括查询词/中英文别名、视觉表示、必要可编辑部件、风格、目标Scene能力和使用限制。采用确定性的词项/标签/结构匹配，不新增embedding模型、向量数据库或LLM调用。

首先检索已有`title/description/semantic_scope/limitations/capabilities`和`recipes.describe`的参数/部件/端口信息；仅在必要时为现有18个条目补少量中英文别名与适用/不适用说明，不重建相同元数据。缺少元数据时明确“未知”，不能因为未声明就假设支持。检索结果包含固定ID/版本、命中依据、缺少的结构、适用范围、参数入口、许可与来源、导入限制；排序分数只是检索排序，不能称语义置信度或科学正确率。

精确品牌/标准标志优先实际存在的官方或授权资产。本地没有时返回unavailable/unresolved，宿主可自行进行正常合法检索；本轮不开发联网爬虫。不能把未知标志改画成“差不多”，也不能捏造mouse/flask/avatar Recipe命中。

### 6.2 候选比较与选择

每个需要选择的对象展示少量相关选项：适合的Recipe、实际存在的合法asset、direct或program路线。可只返回一个确实适用选项，禁止为了凑三个候选创造假资源。

宿主检查必要内部结构、轮廓/画风、可编辑部件、参数覆盖、许可和导入损失后选择。若Recipe只能画通用圆形细胞而参考要求复杂膜和胞器，返回结构不覆盖和program建议，不自动套模板。

必要时可在单独工作目录构造很小的候选预览，再由宿主选取；不默认为全图每个对象渲染所有候选。选择理由保留到planning_context，未选候选不进入当前Scene。

## 7. 显式构造策略与自由编程

将策略作为宿主可组合的画法词汇与选择依据：filled_shape、stroke、boolean_cut、mask、occlusion、overlay、gradient、repeated_instances、text。一个对象可组合多种策略，不把它们再设计成新几何执行语言。

| 策略 | 复用执行能力 | 需要核对 |
|---|---|---|
| filled_shape / stroke | Builder原语、Bezier、明确fill/stroke | 对象是面还是线，真实尖角/边界是否保留 |
| boolean_cut | pathops封闭面差集/复合path | 真孔洞、窄间隙和输入不被破坏 |
| mask / occlusion | 既有Scene0.2效果与局部region | 透明语义、上下次序及移动后有效性 |
| overlay | 普通组和绘制顺序 | 白色实物/表面可以覆盖；背景色盖块不能冒充透明孔洞 |
| gradient | Scene0.3径向/线性渐变 | 连续光影确有需要；扁平参考不暗加立体光影 |
| repeated_instances | 参数/seed、局部变换、独立实例ID | 实例互不串改；示意count不冒充真实分子数量 |
| text | 真text、字体测量、显式换行 | 保留原文与建议的区别、缺字与文字目标尺寸 |

自由Python/JS程序与Recipe地位相同。宿主可用变量、局部坐标、几何库和自己的函数计算形状。程序路线顺序明确为：宿主正常工具显式运行程序→获得Scene片段/摘要和稳定部件映射→construction check→已有FigurePlan/program编译或直接工程候选→必要的B/U/C合并。check/compile没有已准备产物时返回needs_input，不隐式执行源码。不能退化成“必须先手填完大段JSON才允许画图”。

对用户已编辑工程重跑，继续使用B/U/C；候选不直接覆盖当前Scene。加载工程、Bundle、diff和accept都不执行保存源码。

## 8. Evidence：按问题调用的视觉测量

### 8.1 输入输出

在现有Evidence上增加`evidence measure REQUEST --output WORK`文件接口。请求至少声明：源摘要、ROI、待判断问题、测量类型、必要背景/alpha假设、参数与预算。沿用ROI=[x,y,width,height]、bbox=[x0,y0,x1,y1]及明确六元映射，不能混用。输出包含原ROI、映射、方法/阈值、客观测量或候选、可视检查板及限制；状态可为ok/ambiguous/unsupported。

宿主先提出问题，例如“这里是实心色块还是边缘带”“这个白区域是否可能是孔洞”“指定小球在ROI中重复在哪里”。工具不返回“这里就是膜/细胞/靶向箭头”的语义结论，也不把候选自动写Scene。

### 8.2 第一批限定四项

1. **ROI/上下文视图与坐标测量**：复用裁切、缩放、源/ROI/板映射；宿主指定观察位置，不声称自动发现模块。
2. **颜色、alpha和局部剖面**：沿宿主指定采样点/线测颜色、对比、边界带宽候选；不把边缘强度当对象概率。
3. **选定阈值下的连通/孔洞候选**：宿主先指定ROI和前景/背景假设，使用已有NumPy/OpenCV能力返回候选与阈值敏感性。JPEG/阴影/白底不能证明真实透明孔洞，必须由宿主结合原图判断。
4. **给定模板的重复候选**：宿主指定小模板、搜索ROI和阈值，返回相似位置及去重依据；只支持明示尺度条件，颜色近似或低清混淆标ambiguous，不称自动细胞计数。

文字框与转录首版继续来自宿主或显式外部候选，复用`validate_candidates/validate_inventory`核对source和坐标。没有运行OCR就不能返回“自动识别的文字”。不先建设整图文字擦除系统。

### 8.3 缓存与失效

复用源摘要/ROI/参数/实现版本建立内容键；缓存仅含派生测量与视图，不是另一份Scene。更换源、ROI、背景或阈值产生新键。显式记录源坐标，不将放大后的板坐标误作源坐标。

继续现有输入/解码/ROI/板/总派生量预算，限制采样、候选数量和匹配工作量。不为这批工具新增GPU、模型权重或核心重依赖。只在宿主有具体问题时调用，简单任务不先跑全套分析。

## 9. 文字、版式与预览修正闭环

文字和几何职责分开，但共享来源映射和Scene对象ID。参考任务保留original、normalized、suggestion与uncertainty；自然语言任务保留用户给定标签与宿主拟写文案的来源区别。未经明确采用不把建议改进当前文字。

布局首先由宿主确定模块层次、阅读顺序、对象比例和关系端点；使用现有字体测量、显式换行及布局检查，不扩大为通用自动排版求解器。

`plan review`补充规划输入到当前Scene的追踪：必要对象/部件、已选构造映射、文字清单、可机械检查的关系和未解决项；报告“声明存在但未落地”“用户编辑后与输入不同”“需视觉确认”等。不能因存在名为nucleus的path就宣布正确恢复了细胞核。

实际视觉顺序：模块和连接→大轮廓/比例/孔洞→必要内部结构→颜色/层次→文字。读取主图和关键局部；替换旧图时按同尺寸参考/旧版/新版对照。问题关联到具体ID和动作：改构造方法、换候选、调几何/参数、补证据或保留不确定性。默认最多三轮定向修正，不用装饰掩盖缺失结构。

通过后绑定当前Scene/preview记录宿主判断。机械检查、宿主视觉和科学审核仍分开；本轮不安排科学审核。

## 10. 外部方法吸收与局部矢量候选

- **skia-pathops**：继续实际复用唯一主要面域后端。
- **draw-better-svg**：吸收普通程序化构造、局部坐标及inspect→modify→render的方法，不复制无关整套后端。
- **schematic-figure**：吸收模块/对象/文字/关系优先的绘图流程，不引入浏览器核心或把上游名称当本项目已有能力。
- **cell_su7**：吸收文字/几何职责分离、坐标映射、派生缓存；不把去字矢量化当语义理解，也不宣称已做自动OCR去字。
- **Inkvec/VTracer等**：本轮不安装为主依赖、不替换核心。若明确的单区域闭合面需求确有必要，先利用现有可控像素/拟合工具产生隔离candidate，宿主accept/modify/reject。候选不自动获得语义角色、部件树或科学正确性。引入新外部算法需另有具体收益与许可依据，不预设为阶段门槛。

方法借鉴与代码移植分别记录；实际复制外部代码才按固定SHA、文件、许可、修改和验证保留通知。不重新开展大范围外部源码审计。

## 13. 验证：两类任务、少量反例与真实工程操作

### A. 参考图语义复刻

用已提供纳米载体图作为开发案例：宿主先得到制备/给药、肿瘤/血管、细胞放大、图例/色板等结构，分清实体、流程箭头、放大引线和文字。针对确有疑问的局部调用测量，比较Recipe/asset/program，允许复杂部分用自由构造。

必须通过新流程重新产生有记录的决策和产物；旧672对象工程只能作为参考与对照，不能重放旧程序后声称验证了新的语义编排。允许复用已披露的自己构造函数，记录实际选择与修改。

读取新全图与局部，对照参考和上一版；不准为了使用统一模板丢失原有细节。必要结构、可编辑性和目标尺寸可读性是重点，不要求复制原作者控制点。

### B. 自然语言生图

使用用户已经给出的描述：“画一个纳米颗粒靶向肿瘤并通过激光触发释放的机制示意图。”

先将明确内容组织成粒子、肿瘤目标、激光、释放及其说明关系。制备和静脉注射并未由这句话给出，不能擅自作为既定实验过程添加；如采用额外背景，只能明示为插画假设且不改科学含义。宿主设计版式、文字和画风，混合Recipe/自由程序，走同一Scene导出和修正链。

### 小型边界检查

- 扁平简单图：短流程，不自动加渐变或强制每对象先检索。
- 不存在的品牌/Recipe：返回真实空结果/限制，不伪造官方资产；程序路线保持可用。
- 模糊交织局部：局部取证后仍不确定就保留未知，不能仅凭边缘或规则交替猜拓扑。

这些是功能与绘图检查，不重新引入用户排除的正式评测项目。

### 必要工程检查

- 草稿可保留unresolved，compile拒绝未解决构造；关键缺项不被自动补成默认模板。
- 检索只返回已安装和许可明确的实际条目，稳定排序、参数边界、必要部件不覆盖有解释。
- 测量的错源/错ROI/缓存失效/预算/阈值/模板匹配歧义被识别；结果不修改Scene。
- 用户改色、移动、改文字后新候选仍保留编辑；冲突与陈旧接受沿用现有拒绝行为。
- 两类任务均真实改部件、改文字、移动对象、局部导出、保存重开；组合后输入快照和资源引用不丢。
- SVG无嵌入位图/脚本/外链，PNG由同一SVG渲染；视觉记录绑定实际查看的当前结果。
- 跑与变更对应的测试；集成后一次完整回归。之后只有新改动或失败才重跑，不用测试数量证明绘图质量。
