# Scientific Figure Skill 完整执行计划：0.6基础、宿主程序化构造与真实外部Skill验证

## Context

用户需要一个独立、跨宿主的科研矢量重建与绘图Skill：宿主理解参考图或自然语言要求，绘制结构合理、主要部件可分别编辑的SVG；PNG由同一SVG渲染；多个素材能够保存为完整工程并组合为可编辑图组。

0.6已完成证据、上下文、素材包和组合基础，但复杂图仍依赖宿主直接猜坐标与Bezier控制点。交织标志失败、生物局部不确定，说明工程链可靠并不等于绘图方法成熟。外部审计提出的构造式绘图值得验证。本次明确纳入用户新要求：**允许宿主编写Python或JavaScript绘图程序**，用普通算术、局部坐标、重复、成熟几何库和阶段预览完成绘图。

推荐下一轮以Engine 0.7为开发目标：保留现有Scene/Patch/Bundle/组合系统，先真实运行外部Skill，再以薄Python builder＋skia-pathops验证改进，通过门槛后补完整的裁剪、局部交织和安全重跑。本文合并保留既有成果、未完成验收和A—I长期路线，替换旧计划中“仍在0.4、尚未开发0.5/0.6”的过时状态。

**本轮只做只读核查和本计划修订。未安装新依赖、未运行外部Skill、未修改项目源码。实施在计划批准后开始。** 不核实论文，不建设模型服务或供应商SDK，不开发GUI/PPT/Illustrator后端。使用Anaconda `ScientificFigure_skill`、Python3.12、CPU文件CLI；本项目不属于QAagent本体，不初始化Git、不提交或推送QAagent、不部署服务、不上传私有输入。

## 2. 推荐工作流与责任分工

完整工作流：**理解对象与关系 → 选择复用或重绘 → 写构造程序 → 几何库计算 → 结构/几何/样式分阶段预览 → 候选与编辑合并 → Scene提交 → SVG/PNG、编辑与交付。**

1. 宿主声明目标尺寸、主要对象、独立编辑单位、必要孔洞/连接、局部遮挡和未知内容；文字转录与科学关系分别列明。
2. 宿主选择原语、封闭面、中心线、渐变、层叠或许可明确的现成资源。重绘评测与生产复用从此处分组。
3. 简单对象仍可直接写原Plan/Scene；复杂对象允许Python/JS程序，使用变量、普通函数、局部坐标、镜像、旋转、重复、布尔和轮廓计算。推荐复用稳定builder，但不再要求所有几何都手填JSON。
4. 几何库计算具体路径。宿主依次查看主形和比例、孔洞与穿插、文字与样式；每阶段读取实际预览，修正计入统一预算。
5. 程序输出candidate；重跑先与当前用户Scene比较；正式接受通过原工程事务提交。
6. SVG由接受后的Scene生成，PNG由该SVG生成；机械QA、宿主视觉和科学核验分别记录。Bundle/compose继续保存完整可编辑工程。

**Scene是当前生效几何、文字、样式、层级和关系的唯一权威。** 程序、参数和素材来源是可复现输入；preview、objects、manifest和计算路径缓存是派生物。重开、渲染、解包或编辑工程时均不自动执行脚本。

宿主自写绘图程序属于正常工具使用；不建设任意代码执行服务、表达式DSL或AST沙箱。`python -I`不是安全沙箱。外部下载的代码先核对入口和依赖，再按授权的外部验证执行；不自动运行用户上传的未知脚本。允许题图专用构造程序，但不把某几张题图的坐标或分割规则固化成引擎算法。

## 4. 构造工具最小实现

建议新增 `src/scientific_figure/builder.py`、`pathops_backend.py`，先生成普通Scene0.1候选，不先建立复杂构造语言。

| 能力 | 实现与复用 |
|---|---|
| 局部坐标/重复 | 复用`geometry.multiply/point/inverse`，约定先右后左；group/clone/rotate/mirror建立稳定ID与独立副本 |
| 锚点 | 保留`Geometry.anchor()`的世界bbox锚点原语义；新增程序内显式局部锚点，不把保守bbox说成精确轮廓特征点 |
| 曲线 | 复用`curves.fit_open_path/smooth_path`及fit CLI；明确后者是闭合polygon平滑、误差为采样残差，不承诺任意Bezier优化/无自交 |
| 封闭面域 | pathops union/intersection/difference/xor；复合环、fill-rule、镜像绕向、空结果均有明确转换；现有`geometry.union()`只是bbox合并，不替代面域运算 |
| 描边转轮廓 | 首期定宽、round cap/join，与现有输出语义一致；明确先在局部做stroke再仿射，非均匀缩放不偷换为世界均匀线宽 |
| 序列化 | 集中处理SVG path↔pen↔pathops，显式记录conic近似容差和实际输出；有限数值、退化、细缝、段数/工作量预算；不静默简化掉孔洞 |

首次安装优先目标平台wheel，不默认在本机拉完整Skia/C++工具链。发行版本与已读源码SHA不必相同，必须如实对应；API与结果不符就先修适配或记录阻断，不默默换双主后端。`Path.stroke()`会原地修改路径，适配层必须复制输入，保护源中心线和生成基线。`convertConicsToQuads(tolerance=.25)`有细分上限，不能把该参数宣称为已保证的最大误差；实际检查圆弧/高曲率/细带及不同尺度下的偏差、段数、孔洞和间隙，首版不默认叠加平滑。

首个原型只做少量对象：不规则轮廓、真孔洞、局部交织。宿主程序用参数和几何运算完成，不复制其他试验臂最终path。首期静态Boolean结果可以编辑，但不宣称移动后自动更新关系。变量宽笔画先作为小实验，真实案例需要且稳定后才纳入，不拖入主依赖。

**推进门槛**：结构达到该试验任务要求，且构造/修正耗时、手填几何或修正次数至少一项出现可记录收益，其他关键质量不退步。小样本仅作继续开发的依据，不作统计泛化结论。若仍主要靠大量猜控制点或关键交织错误，先改构造工具/方法，暂停后续格式扩张。

## 5. 宿主程序、candidate与用户编辑的合并

### 5.1 最小来源记录和入口

拟新增 `generation.py`与严格generation/candidate契约；在`project.py`注册必要JSON extras，接入复制、回执、Bundle和复核绑定。`generation.json`保存语言、脚本源码/摘要、参数快照、输入与后端版本、生成范围和上次纯生成基线。源码作为数据保存，不在加载时执行；去除临时绝对路径作为唯一来源。

程序由宿主用正常工具运行，输出候选目录。拟新增 `figure-cli generation diff PROJECT --candidate DIR` 和 `generation accept PROJECT --candidate DIR --base-revision N`：diff给出候选合并Scene/预览与冲突；accept只接受已有候选，不提供自动运行任意脚本入口。首次创建新工程仍可走draw；已有工程先diff再提交。

生成基线按稳定对象/资源/关系ID及相关语义状态规范化，不含自己的binding摘要、receipt、时间戳等，避免递归摘要与伪冲突；记录生成所有权范围，不把用户新增对象归为生成物。

### 5.2 B/U/C三方比较

B是上次已接受的纯生成结果，U是用户当前Scene，C是本次新候选。首轮以对象/资源的类型、parent、geometry、style属性、关系和兄弟顺序为比较单位；path、矩阵、有序数组按原子字段处理。

| 情况 | 合并行为 |
|---|---|
| U等于B，C改变 | 提议采用C |
| C等于B，U改变 | 保留U |
| U等于C | 无冲突 |
| 双方改变同一字段且不同 | 冲突，保留U |
| 删除遇到修改、新ID碰撞、引用无法闭合 | 冲突，不自动删除/覆盖 |
| 共享资源、parent或兄弟顺序改变 | 参与同一次比较和引用校验，不只替换对象子树 |

几何依赖也参与检查：用户改操作数后，候选烘焙的下游path可能过时；必须基于合并操作数重求值或报冲突，不能以“不同字段”直接通过。未解决冲突不改变当前工程；可显式选择冲突项后重新生成完整合并候选。成功后纯生成基线更新为C，不能用混入用户编辑的合并Scene替代B。

候选绑定U的revision＋内容SHA，接受时再次核对；先完成Schema、上下文、typed refs和渲染验证，再通过`apply_patch/structural_patch`及`write_project(expected_revision=...)`事务提交。现有Patch不能表达清除、重挂父级等时扩展新版本；不把`replace_subtree.id_map`当作完整语义引用迁移。

必须实际验证用户改色、移动、改path、增删对象、修改资源、重排后重跑。结果给出保留项、更新项和冲突，不静默覆盖。失败候选单独保存，不塞进当前权威工程。

## 6. Scene0.2：真实裁剪、遮罩和局部交织

### 6.1 最小模型与求值

新增Scene0.2，保持Scene0.1严格原义；引入有类型clip资源、受限alpha mask及局部occlusion关系。关系至少包含稳定ID、over/under对象引用、显式局部region、region所属坐标框架和gap。首期over/under操作数限定可计算的封闭填充或定宽轮廓，不任意对text、connector、含复杂透明组求布尔。

- 封闭形孔洞用真实复合路径/差集；裁剪保留源几何。不得用白色或背景色覆盖块假装镂空。
- 局部交叉从双方当前原始几何计算，转换到声明的共同坐标系，在region内切除under的被遮部分及明确余量，再映回目标局部。gap单位、变换、stroke处理统一定义。
- 同一对带可在不同region反转上下关系；全局over/under可以成环，计算始终读取源几何，不递归读取对方裁剪后的结果。重叠region存在矛盾时拒绝或报告需宿主处理，不猜交织。
- 源路径、宽度、transform和关系属于Scene；切除后的路径/clip是确定性派生结果，不与源几何形成第二套编辑状态。显式“解除关系/烘焙”才转为普通静态path。
- region绑定对象或公共组须明确。整体移动随声明框架移动；移动任一带、旋转、改宽或曲线后重新求值。交叉离开region、消失或出现额外交叉时报告关系失效/需复核，不能沿用旧遮挡报成功。
- 首期alpha mask明确`userSpaceOnUse`、region和alpha语义；不支持外链、位图、filter或任意混合。半透明遮挡不伪装成硬切；超出定宽/封闭面支持范围明确unsupported。

### 6.2 全链覆盖，不能只加SVG标签

| `composition.py`、选中导出 | 全部对象/资源/region框架/over-under引用重映射；不硬编码输出Scene0.1；完整组合保留关系 |

普通几何bounds、保守可见bounds和真实像素覆盖分开。保护项被clip/mask完全遮掉时不能仅凭原bbox通过；机械方法不足以证明覆盖时标needs_review，交给视觉复核。资源内路径也计复杂度，不能藏进defs绕过预算。

局部静态导出默认在当前状态烘焙受外部对象影响的遮挡，保持当前外观且不意外导出未选对象；完整工程保留live关系。烘焙行为与connector冻结一样明确报告。若提供保关系工程导出，必须包含完整依赖闭包。

**功能门槛**：白/深/彩色/透明背景均正确；分别移动over、under和整体组，改宽/旋转/曲线后当前预览正确；镜像、非单位父变换、克隆两实例仅改单个后仍正确；保存、组合、Bundle及导出无丢引用。初次渲染正确只算静态构造，不算持续可编辑交织完成。

## 7. 有许可资源复用与受控SVG转换

生产任务允许复用，记录来源URL、版本、SHA、LICENSE/通知、原作者及修改；版本匹配的项目资源优先。外观相似或网上可下载不等于授权复用。私有图和派生工程留本地。
