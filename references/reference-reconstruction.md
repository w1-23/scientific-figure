# 参考图语义复刻：从信息结构到可编辑构造

目标版本0.9；已建立的实现基线为Engine0.8.0。当前宿主负责读图、解释和视觉判断，不调用第二模型。工具入口与实现状态见[语义规划工作流](../docs/semantic-planning-workflow.md)，构造能力见[0.8用法](../docs/drawing-workflow-0.8.md)。

## 1. 先读整图，不先描轮廓

确认用途、目标展示尺寸、是否允许风格简化及必须保留的文字。先沿标题、编号、箭头和空间分区找阅读顺序，再区分各区的作用。空间相邻不等于科学连接；边缘、颜色相近也不意味着同一对象。

| 读图项 | 要写清的判断 | 常见误读 |
|---|---|---|
| 信息模块 | 每区说明什么、从哪读到哪、是否并列或分阶段 | 把一个放大视图读成下一实验步骤 |
| 实体及必要部件 | 外边界、内部腔体/膜带/核心、重复单元、可编辑单元 | 用一个圆和对象名称替代复杂内部结构 |
| 关系 | 起终对象/部件、方向、可见端点、线型及作用 | 把标注引线画成流程箭头，或把放大框当容器 |
| 前后层次 | 哪些边界延续、在哪里被遮挡、是否有局部穿插 | 凭规则交替推断所有交叉的上下关系 |
| 文字与色义 | 原文、位置/归属、图例对应、类别色或明暗色 | 将文字建议直接当原文，或把不同类别并色 |
| 未知 | 具体位置、缺少什么证据、影响哪个决定 | 写笼统“低清”，随后按主题补造结构 |

先形成一个小草稿：模块 → 对象与必要部件 → 关系 → 文字/色义 → 未知。复杂图可放进已有FigurePlan的modules、objects、relations及对应声明；尚未选画法的对象保持unresolved。草稿不是第二套当前几何，不能为记录方便擅加严格协议未知字段。

## 2. 只为会改变画法的问题取证

按影响排序处理未知：会改变连接/孔洞/对象身份的优先，轻微颜色和纹理次之。先看源图与带上下文的局部，再决定是否需要测量。放大不会增加原始信息。

- **白区是孔洞还是白色物体？** 看边界是否连续、背景能否透过、前后关系是否支持。JPEG白底或阈值连通结果不足以证明透明孔洞。
- **细带是线还是面？** 看宽度变化、封闭边界和折叠。膜带可用封闭面加独立褶线，不强制抽骨架。
- **重复图元有多少、朝向如何？** 先指定可辨模板与范围；低清重叠处保留计数未知，不把示意重复当真实分子数量。
- **字或端点看不清？** 保存可见部分和具体疑点；没有实际运行OCR就不能宣称自动转录。文字候选须保留来源和坐标。

采用的证据记录原文件摘要、ROI、方法/参数、坐标映射及限制。ROI为[x,y,width,height]，bbox为[x0,y0,x1,y1]；板坐标须按映射回源/Scene。仅用实际可用的工具；0.9新增测量入口是否已落地，以工作流页为准。问题仍无解时，保留unknown、采用明确披露的可见近似，或索取会影响科学含义的必要信息。

## 3. 结构草稿通过后再选择画法

按[构造选择表](construction-selection.md)比较必要部件、形态、画风、编辑要求及资源限制。复杂膜、特殊鼠体或折叠结构若不被现有Recipe覆盖，必须回退自由程序或混合构造；不能用通用图标替换必要结构。先做主要轮廓与必要部件的小预览，再细化。保留稳定组/部件ID，把同一语义对象的填充、褶线与文字分开编辑。

源码由宿主显式执行。新工程可直接构建；已编辑工程以B=上次纯生成、U=当前用户Scene、C=新纯候选做diff，检查合并预览与冲突，再按revision接受。当前Scene权威，不从输入草稿静默恢复用户改色、移动或文字。

## 4. 小型完整示例：带放大局部的双层颗粒

**输入与解释。** 参考为扁平图：左侧一颗双层颗粒，右侧放大其外壳，虚线连至放大圆；两条引线分别标“壳层”和“核心”。目标宽120 mm。整图只有“整体—局部解释”两个模块；虚线是放大关系，两条细线是标注，均不是制备流程。

**必要内容与未知。** 颗粒须有独立外壳、内层、核心和两条真text标签；放大区保留两层厚度关系。右上白缝无法判定是开口还是高光，记录其位置与不确定性，先查看该处源图裁切；仍不清楚就保留外观近似，不声称恢复了真实孔洞或背侧结构。

**选法与执行。** 简单圆形由direct构造；放大外壳若有不均匀折叠，用自家局部曲线函数写program，不能套缺少折叠部件的细胞Recipe。用局部组统一缩放，独立文字用字体测量定位，显式连接放大端点；运行得到候选Scene并渲染。

**检查与修正。** 实际目标尺寸预览先查放大线是否被误加箭头、内外层是否可辨，再看局部白缝。若内层被外壳盖住，只改对应部件和次序，重新渲染检查。绑定当前预览的视觉记录，保存工程与同源SVG/PNG；披露使用的自家函数、渲染库及白缝未知。若替换旧版，同尺寸比较参考/旧/新，不能因接口通过就称新图更好。

## 5. 停止与交付

默认最多三轮定向修正：模块/连接 → 轮廓/比例/孔洞 → 必要内部结构 → 颜色/层次 → 文字。每项问题写ID、可见证据、修改动作和剩余未知。机械检查、宿主视觉与科学审核分别记录；路径名或测试通过不证明对象恢复正确。未通过的部件如实保留，不用装饰掩盖。

外部素材、自家/外部绘图函数、几何与渲染库分别披露。私有参考、题图程序和派生工程仅本地分包；不进入公开示例，不打包系统字体。工程打开、Bundle加载和候选接受均不执行保存源码。其余边界沿用[绘图规范](drawing-policy.md)。
