# 构造选择：先看形态、部件与画风

目标版本0.9，实际基线Engine0.8.0。配合[参考任务](reference-reconstruction.md)或[文字任务](text-design.md)使用；新检索/规划CLI及实现状态见[语义规划工作流](../docs/semantic-planning-workflow.md)。宿主作选择，工具返回的排序或检查结果不替代语义与视觉判断。

## 1. 把需求写成可比较的条件

选画法前先答六个问题：主形态是面、线还是组合？哪些内部部件不可省略？是否重复且要独立编辑？是否有真孔洞/遮挡/局部穿插？画风是扁平、带体积还是笔绘近似？最终尺寸下哪些细节仍须可辨？再检查字体、资源许可与导入损失。不要按“细胞”“鼠”等名字直接套模板。

| 路线 | 适用条件 | 选择前检查 | 不适用时 |
|---|---|---|---|
| Recipe | 实际模板的必要部件、参数范围和风格覆盖需求 | `recipe describe`的部件键、ports、版本、seed及限制；参数合法仍需预览 | 必需部件不覆盖，必须回退program/direct或混合构造 |
| 合法asset | 存在可用授权矢量且编辑/风格要求适配；精确标志优先授权源 | 作者/许可、固定版本、原始与分发SHA、修改、导入子集、部件可编辑性 | 不存在就标unavailable；不能造一个“近似官方”资源 |
| direct | 简单形状、标签、线或已有明确Scene几何 | 真text、稳定ID、局部变换、资源闭包 | 重复/复杂计算较多时转program |
| program | 特殊轮廓、复杂内部结构、重复、程序化曲线或混合构造 | 自家函数适配、依赖、稳定部件映射、实际Scene能力与数值限制 | 先做最小结构预览，改算法/画法或保留具体未知 |

当前本地目录为15族Recipe、2个符号族元数据及1个Twemoji柠檬资产；符号族元数据不等于已有可导入素材。没有mouse、flask、avatar Recipe。按实际安装版本查询，不捏造候选。简单图可以直接选direct；只有确有比较价值时才查目录或做局部候选预览。无需每对象凑三个选项。

## 2. 对象可以组合多种构造策略

下表是画法词汇，不是新DSL，也不替代现有Scene能力边界。

| 策略 | 何时使用 | 必查问题 |
|---|---|---|
| filled_shape | 外壳、实体、宽度变化的膜带等封闭面 | 真实锐角、窄缝、内外边界、fill-rule；不将薄带一律骨架化 |
| stroke | 引线、路径、定宽中心线、独立褶线 | 线宽/端点/连接、箭头角色；不要用狭长填块替代所有细线 |
| boolean_cut | 真孔洞、面域差集、轮廓合并 | 封闭输入、孔洞拓扑；唯一主要面域后端skia-pathops，float32与弧线近似仍需看图 |
| mask / clip | 有界矢量裁切或透明度变化 | 局部坐标、alpha语义、资源范围；不是任意滤镜或位图遮罩 |
| occlusion | 需要编辑后重算的局部上下关系 | 明确双方、frame、region和gap，检查支持条件及移动后diagnostics；不自动推断新交叉 |
| overlay | 实物表面的叠放、普通前后层次 | 背景色盖块不能冒充透明孔洞；静态层叠不能假称持续穿插 |
| gradient | 参考/设计确有连续明暗的形体 | 使用真实线性/径向渐变；扁平图不自动加阴影 |
| repeated_instances | 颗粒、图元或装饰的可控重复 | 独立实例ID、局部变换、seed；示意数量不冒充实际计数 |
| text | 标签、图例、标题 | 真text、字体SHA、目标尺寸可读性、显式换行；不静默改字或轮廓化文字 |

例如复杂膜可组合封闭面、布尔开口、独立褶线和局部遮挡；球形颗粒可用面加重复实例。策略应解释结构，不能靠增加路径数和渐变掩盖缺件。

## 3. 用覆盖情况淘汰候选

保留少量相关候选，逐项比较“必要部件覆盖、轮廓与画风、编辑性、参数/引擎能力、许可/损失”。只对难决策的关键对象做小预览。记录所选方法、满足哪些条件、拒绝其他方案的具体原因和剩余未知；不将检索分数叫语义置信度。

**完整小例：不规则开口膜与内部折叠。** 需求是扁平不规则膜、一个真实开口、三条独立褶线，移动后仍可编辑。现有通用cell_symbol候选须先查describe；若仅有通用轮廓/部件，参数不能覆盖开口和折叠，就拒绝整对象套用。选择program：自家曲线函数生成膜面，skia-pathops切出真实开口，褶线为独立stroke，统一放入局部组。先看目标尺寸预览；若开口被细轮廓遮住，改开口几何和边线，而非叠白块。渲染复查、记录部件映射并保存工程；若原工程有用户编辑，先diff合并再接受。披露自家函数及pathops/resvg的实际使用；未用外部素材则明确无素材复用。即使所有参数/测试通过，也须由宿主确认实际轮廓与必要结构。

## 4. 程序路线与工程更新

宿主可直接写Python/JavaScript，用变量、局部坐标、成熟库和自己的函数计算Scene片段。顺序是：显式运行程序 → 得到已生成的Scene与稳定部件映射 → 按已实现入口校验/编译 → 新工程或候选 → 实际预览。program不是源码执行器；没有准备好的片段就应补输入，check/compile不暗中运行代码。`python -I`不是安全沙箱。

重跑沿用[生成事务](../docs/generation-and-effects.md)：B为上次纯生成，U为当前Scene，C为新纯候选；检查diff的合并预览与冲突，再用当前revision接受。用户同字段异改保留U并报告；成功基线更新为C。Plan、参数与选择记录是输入，Scene是唯一当前状态。不要为复用旧程序直接覆写工程。

## 5. 分开披露三类复用

- **外部素材：** 实际采用的文件/作者、许可、固定版本、原始及分发摘要、改动和导入损失。目录里存在不等于本图用过。
- **绘图代码：** 自家函数记录文件/版本或摘要、复用部件和本次修改；外部复制代码另留固定SHA、文件、许可及通知。仅吸收方法也与复制代码分开记录。
- **几何/渲染库：** 记录实际库/版本和承担的操作，如pathops布尔、FontTools变换/字体测量、resvg渲染。调用库不等于借用外部画作。

私图及题图函数不固化成通用题材核心或公开示例；系统字体/环境/权重不随包分发。合法复用与明确要求的冻结栅格重绘分别说明。默认最多三轮针对结构与可读性的实际预览修正，不新增正式pilot、大评测、盲评或科学认证门槛。
